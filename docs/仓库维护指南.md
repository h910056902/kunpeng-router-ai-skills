# 仓库维护指南（Maintainer Guide）

> 给未来接手维护本仓库的 AI / 人。目标：**5 分钟内知道改哪里、怎么验证、怎么发布**。

## 一、仓库布局与职责

```
AGENTS.md            AI 机器可读入口（§8 = 菜单助手协议，菜单文本唯一真源，改菜单先想到这里）
llms.txt             LLM 低 token 索引：每加/删一个文档都要在这里登记一行
SKILL.md             人类可读索引（路由表 + 踩坑速查），AI 不通读
tasks/index.json     机读任务清单（46 个任务），每条含 id/risk/playbook/preconditions/verify/rollback
tasks/*.md           安装与运维 playbook（01~10，每份都是 前置→步骤→验证→回滚→已知坑）
references/          23 篇专题档案，每篇顶部必须有 frontmatter（id/tags/risk/preconditions）
docs/                经验总览、验收清单、助手菜单提示词、本指南
assets/menu/         菜单图标（10 枚 32px PNG，纯标准库生成的，不要从别处抄素材）
offline/             版本钉死的离线素材 + checksums.md5（二进制改动后必须重生成）
scripts/             PC 侧驱动脚本（凭据只走环境变量）+ payload/（设备端脚本与 fixtures）
```

## 二、常见维护场景

### 1. 新增 / 修改一个任务
1. 在 `tasks/index.json` 加（或改）一条：`id` 必须唯一、`risk` 如实标、`playbook`/`refs` 指向真实路径
   （`order` 取当前最大值 +1 —— 本仓库现在最大是 138）
2. playbook 写全五段：前置条件 → 步骤 → 验证命令 → 回滚方法 → 已知坑
3. `llms.txt` 的 Tasks 段补一行摘要；`SKILL.md` 路由表同步
4. **任务计数要跟着改（4 处）**：`llms.txt`（「全量 N 个」）、`AGENTS.md`（「全量 N 个」）、
   `README.md`（「N 个任务」/「N 个机读任务」）、本指南（「N 个任务」）—— 自检有「任务计数一致性」守卫，漏一处直接 FAIL
5. 跑 `_selfcheck.py` —— 路径引用检查会抓出悬空引用

### 2. 改菜单（AGENTS.md §8「菜单助手协议」）
1. **菜单文本只有一处真源**：只改 §8.2 的【菜单】块。§8.0 的一段话启动器**自带公开仓地址**（固定值，通常不用动）
2. 重放 README：`Copy-Item _readme_template.md kunpeng-router-ai-skills\README.md -Force`（构建脚本不生成 README）
3. 跑 `_selfcheck.py` —— 它把 §8.0 的启动器与 §8.2 的菜单块对 README / `docs/助手菜单提示词.md`
   做**逐字同源校验**，飘一个字就 FAIL（这是「只留一处真源」的保险）
4. 新增菜单项：补 `assets/menu/<name>.png`（32px）→ §8.1 图标行加一枚 → §8.2 加一行 →
   `_selfcheck.py` 的 `PROTOCOL_ANCHORS` 与图标资产清单各加一项
5. **锚点字符串必须与正文逐字一致**：正文里给 `text` 或任务 id 加了反引号，锚点也要跟着加，
   否则自检误报「缺协议锚点」（真踩过）

### 2b. 新增一个「菜单分类」（本仓库 2026-09-19 刚做过一次，照这张清单走）

菜单 5)~9) 是第三方脚本（maye 助手）的五个功能分类，每个分类**不是**「跑一遍 tasks/05 就行」——
它们各有自己的红线与判据。加一个新分类要动 **9 个地方**：

| # | 改什么 | 注意 |
|---|---|---|
| 1 | 新增 `tasks/NN-nros-<分类>.md` 分册 | 结构照抄 `tasks/06`~`tasks/10`：本分类红线 → 上游菜单**真源**（逐字 + 行号）→ 本机可用子集 → 前置 → 执行（AI 做 / 你按）→ 验证 → 回滚 → 已知坑 |
| 2 | `tasks/index.json` 加一条 | `risk` 如实标（改网络平面 / 下载未校验 root 脚本 → `destructive`） |
| 3 | `AGENTS.md` §8.2 菜单块加一行 | 这是唯一真源 |
| 4 | `AGENTS.md` §8.3 解析输入的编号范围 | `1`~`9` → `1`~`10`；「固定顺序」也要改 |
| 5 | `AGENTS.md` §8.5 功能与依据表 | 加一行（playbook 路径） |
| 6 | `AGENTS.md` §8.6.1 差异速查表 | 加一行：该分类的额外准备 + 禁选项 |
| 7 | `AGENTS.md` §8.7 第 7 条的禁选项 | 按分类加 ⑧⑨… 并写清**为什么**（不给理由 AI 会照选） |
| 8 | `assets/menu/` 补一枚图标 + §8.1 图标行加一枚 + 自检资产清单加一枚 | 三处必须同改 |
| 9 | 计数与文档：`llms.txt` / README 模板 / 本指南 + `_readme_template.md` 的任务包表 | 见 §二.1 第 4 步 |

> **上游真源怎么取**：不要照 README 转述（README 会漏机型限制与破坏性分支）。
> 把 `installer.sh` 拉下来，按 `print_menu_header` / `print_menu_item` / `run_menu_feature` 三类
> grep 出菜单树，再读每个分支函数的前 20 行看它 **guard 判据**（`*_model_supported`）与
> **写盘语句**（`uci set` / `ip rule` / `rm` / `fw3 reload`）。写 playbook 时把**行号**钉进去 ——
> 下一位维护者能自己复核。

### 3. 改 references / docs
- 新文档必须带 frontmatter（`id: REF-xxx` / tags / risk / preconditions），自检会数篇数
- `llms.txt` 登记一行（一句话说清"读完能干什么"）

### 4. 更换 offline 素材
1. 二进制文件（.ipk / .gz）不要走文本脱敏，`.gitattributes` 已钉 `-text`
2. 换文件后跑 `_regen_md5_public.py`（公开仓）与 `_regen_md5.py`（私有仓）重生成 checksums.md5

## 三、公开仓发布流程（每次改完私有仓必走）

```powershell
# 1. 重建公开仓（脚本会覆盖式重建 stage，包括 README.md 和 .git —— 属预期行为）
python _build_public_repo.py
#    §3b 自动适配：tasks/index.json 的 repo 字段 -> kunpeng-router-ai-skills
#        （AGENTS.md §8 里写死的仓名就是**公开仓**名 —— 启动器正文自带公开仓地址、图标走公开仓 CDN，故无需替换）

# 2. 重写公开仓 README.md（从 git 历史或私有模板重放；构建脚本不生成它）
Copy-Item _readme_template.md kunpeng-router-ai-skills\README.md -Force

# 3. 接回 git 历史（避免 force push）
git init -b main
git remote add origin https://github.com/h910056902/kunpeng-router-ai-skills.git
git fetch origin main
git reset --soft FETCH_HEAD   # 取远端 sha 软回退，历史不断
git add -A; git commit -m "..."

# 4. 重生成 md5 + 自检（⚠️ 必须在 commit 之前跑：自检失败时不该已经产生提交）
python _regen_md5_public.py
python _selfcheck.py            # 须 ALL CHECKS PASS

# 5. 推送（本机 github.com DNS 被污染，直推会静默 rc=128）
python scripts/gh_proxy_push.py push <仓库路径> main
#    判据只有一条：输出的 MATCH : True
```

## 四、发布前红线（违反任何一条都不许推）

1. **脱敏**：`_build_public_repo.py` 的 RULES 命中数要与上次持平或可解释；`_scrub_report.txt` 的「疑似项」逐条过目
2. **仓名**：公开仓内不得出现 `kunpeng-router-tuning 之上` 字样（私有仓文档描述公开仓时用「私有仓 kunpeng-router-tuning」整句提法，属允许范围）
3. **凭据**：所有脚本凭据只走环境变量；`offline/openclash/config.openclash.template` 的 `<...>` 保持占位符
4. **md5**：checksums.md5 对账必须 bad=0
5. **真实来源**：references 只收真机验证过的结论；推测性内容不进库；**playbook 里的上游行号必须能复核**

## 五、已知坑（改代码前先看）

- `_build_public_repo.py` 的 `place(srcrel, dstdir)` 落盘位置 = `dstdir` + 源文件的 basename，**源路径里的目录前缀会被丢掉**，目标子目录必须由 walk 调用方自己拼好；新增顶层目录时照抄 tasks/docs 的 walk 块即可
- PowerShell 工具在本机**不回传 python stdout**：一律 `> file 2>&1` 重定向后再读；文件带 BOM/二进制前缀时用 `[System.IO.File]::ReadAllText(path, UTF8)` 转码
- 本机 Bash 工具不可用（dirname 缺失），git/python 都走 PowerShell 原生调用
- **一次性同步脚本要防「三引号切断函数体」**：`def main():` 里写 `header = """# 标题` 这类「引号紧跟内容」的多行串，若后续内容顶格，Python 会在该串闭合处**结束 main()**，余下语句落到模块级 → 报 `NameError` 且 **main() 根本没执行**（最容易误判成「已改好」）。写完先确认它真的生成了自己的 report 文件
- **不要靠 console 输出判断成败**：同步/发布脚本一律让它们自己写 report（`_v2_sync_report.txt`、`_stage_git_out.txt`、`_priv_push*_out.txt`…），Read 那个文件才算证据。PowerShell 工具吞 stdout 时，「看起来没输出」不等于「没执行」
- ~~菜单提示词同一段文本在仓库里有三份~~（2026-09-19 已修）：现在**一处真源 + 机器校验** ——
  `AGENTS.md` §8 是唯一真源；`docs/助手菜单提示词.md` 与 README 只放一段话启动器（README 另有展示预览），
  由自检的逐字同源校验兜底。**别再把菜单全文复制到第三处** —— 那正是当初「改一处漏两处」的根源
- **改架构时，描述旧架构的维护文档会同步变成误导**：菜单从 4 项扩到 9 项时，§二.2 的「三处同改」、
  「新增菜单项只改 4 处」等旧清单全都失效 —— **必须一起改**，否则下一位维护者照老规矩把菜单又复制回第三处
- **自检锚点必须与正文逐字一致**：锚点写 `一个 text 代码块`、正文却是 `` 一个 `text` 代码块 ``（带反引号），
  就会误报缺锚点。改文案时同步改 `_selfcheck.py` 的 `PROTOCOL_ANCHORS`
- **替换式补丁必须幂等**：`old` 若是 `new` 的子串，`count(old) == 1` 这种断言**拦不住重复应用**——第二次跑会把补丁叠一遍（本手册真被叠过一次）。判据改成「`new` 已存在就跳过」，并给脚本加 lock 文件防重复执行
- **沙箱对「每轮删除对象数」有硬上限（50 项，`scope: turn`）**：`shutil.rmtree(STAGE)`（公开仓 137 项）
  会被 `SAFE_DELETE_BULK_CONFIRM_REQUIRED` 拦下，而且**脚本会删到一半就中断** —— 公开仓被搞成半残
  （2026-09-19 真踩过：`offline/` 与 `offline/core/` 的大文件被删掉、`.git` 被破坏、构建中止）。
  注意：**改成分小批删除也绕不过去**，因为计数是按整轮累计而非按单次调用。对策：
  ① `_build_public_repo.py` 现在**不做清空**，改为**覆盖式重建**（清单内文件全部重写），
     清单外残留由 `_selfcheck.py` 与人工复核兜底；② 需要真正清场时用**改名外移**
     （`os.rename` 不计删除数），跨轮再删或直接留着
- **落盘复核的判据要用「`new` 出现且唯一」，不能用「`old` 消失」**：当 `new` 以 `old` 为前缀
  （最常见的「在原文后面补一段」写法），`old not in back` **恒为假**，会把成功写入误报成失败
  （2026-09-19 实测：13 处补丁里有 2 处被误报，实际都已正确落盘，白查了一轮）。复核一律写
  `back.count(new) == 1`
