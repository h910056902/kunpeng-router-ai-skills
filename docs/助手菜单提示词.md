## 六个关键点（为什么这样写）

1. **菜单必须包在 text 代码块里输出**——聊天界面会把 Markdown 列表自动重编号，「0) 退出」会被渲染成「4. 退出」（实测翻过车），`===` 标题和对齐也会被吃掉；代码块是唯一能保住原样的输出方式。
2. **首输出必须逐字只有菜单**——不加「静默 + 逐字照抄 + 禁止清单」的话，AI 会先客套一句「好的，我正在读取仓库」，菜单仪式感全毁，还可能顺手往下跑。
3. **菜单必须带任务 id**——只写「1) 装 OpenClash」的话，AI 不知道该读哪个任务包，会自由发挥；playbook 路径放「功能与依据」段，菜单行保持干净。
4. **输入语法要穷举**——单选、多选顺序、退出、非法输入都写死，否则 AI 自己发明规则。
5. **范围边界写死到 id 级**——store.* 列出全部 4 个具体 id，加上 AdGuard / NAS / Portainer 汉化；不然 AI 看到 index.json 里还有 30 多个任务，很容易顺手多装。
6. **4) 必须单独交代"第②关拆两半"**——它是交互式脚本（清屏 + 10 秒倒计时 + 读 stdin 输入 y），
   不写这条，AI 会用 `exec_command` 或管道去"帮你跑"，直接 `input cancelled`；更糟的是它会顺手
   替你在菜单里选（playbook 里全是"怎么装"，它不会自己拦住"卸载 Docker"）。
   同时把四条红线提升成硬约束第 7 条——playbook 给愿意读文档的 AI，硬约束给"直接开干"的 AI。
