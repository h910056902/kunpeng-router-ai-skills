## 为什么 4)~9) 必须单列（不能照 1/2/3 的写法）

1. **它是交互式的，AI 不该替它做选择。** 启动 = 清屏 + 10 秒免责声明倒计时 + 读 stdin 输入 `y`。
   实测三种喂法：`< /dev/null` → `die "input cancelled"`；`exec_command` 不喂不关 → **永久挂住**；
   管道喂够 `y`+编号 → 其实能跑通（rc=0）。**技术上能自动化，但绝不许** —— 那等于替使用者选菜单项，
   而菜单里有「卸载 Docker」「还原应用商店」。→ 第②关必须**拆两半**并写明「停下等使用者」。
2. **它菜单里有能毁设备的选项。** playbook 通篇是「怎么装」，AI 不会自己拦住「卸载 Docker」
   （`rm -f /etc/config/dockerd` = 1Panel 环境 + 容器数据一起报废）→ 红线必须写进**协议硬约束**，
   不能只躺在 playbook 里（playbook 给愿意读文档的 AI，硬约束给「直接开干」的 AI）。
   现在红线按分类拆成 7 类（§8.7 第 7 条），例如「哈基米＝装 OpenClash」「还原应用商店＝抹掉补丁 marker」
   「`5 › 11` 硬件加速＝`fw3 reload`」。
3. **它不产生任何备份。** `backup_file()` 是空实现（`return 0`），`BACKUP_DIR="/root/nradio-plugin-fix"`
   是死路径（真机 `ls -ld` → No such file）。所以「跑前自己备份」是硬前置，不是可选项。
4. **版本门禁有坑。** 判据读 `ubus call system board` 的 `release.revision` = `2.3.0.n0.c1`，
   而不是 `/etc/openwrt_release` 的 `DISTRIB_RELEASE='21.02-SNAPSHOT'`；只看后者会误判「会被脚本拒绝」。
5. **每个分类要挡的东西不一样。** 6) 挡的是「`ip rule` 一改就断网」，7) 挡的是「明文 HTTP 下载的 root 脚本」，
   8) 挡的是「商店补丁被抹」，9) 挡的是「`fw3 reload` 重建 nat 链」。
   把这些混在一份 tasks/05 里写，AI 读不过来 —— 所以拆成 `tasks/06`~`tasks/10` 五份分册。
