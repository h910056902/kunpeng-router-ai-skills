# 鲲鹏 C2000 路由器调优经验总览

> 面向 AI Agent 与人类读者。每条经验的格式：**结论 → 为什么 → 怎么验证**。
> 详细证据链见 `references/` 对应专题文档；设备硬规格见 `SKILL.md` 的「设备档案」。
> 全部结论来自**真机实测**（C2000 Max + C2000 U），非文档抄录。

## 0. 三条底层事实（后面所有坑的根源）

| # | 底层事实 | 直接后果 |
|---|---|---|
| 1 | **内核没有 veth**（厂商没编译，`kmod-veth` 是空包，`lsmod \| grep -c '^veth'` = 0） | 容器只能用 `--network host`；**不能端口映射**；所有 bridge 配置调整都是白费 |
| 2 | **UCI 是唯一配置入口**（`dockerd` 每次启动都用 UCI 重新渲染 `/tmp/dockerd/daemon.json`） | 直接写 `/etc/docker/daemon.json` **完全没人读**；改 daemon 必须走 UCI 或 `alt_config_file` |
| 3 | **opkg 在「选候选包」阶段就会拒**（`--force-depends` 只管「装包时」的检查） | 缺依赖时唯一干净出路是**造 stub ipk**；厂商内核缺的 kmod 在官方源里装了也加载不了（vermagic 不匹配） |

## 1. 平台、内核与资源

**① 无 veth 是真约束，不是配置错误。**
容器报 `failed to add the host (veth...) <=> sandbox (veth...) pair interfaces: operation not supported` 时，**不要去调 bridge / iptables / daemon.json** —— 就是内核没这个模块。
验证：`lsmod | grep -c '^veth'` → 0；`docker run --rm --network host hello-world` → 立刻成功。

**② 别因为「没有 veth」就以为代理也跑不了。**
实测 `CONFIG_TUN=m`（`modprobe tun` OK，`/dev/net/tun` 在）与 `CONFIG_NETFILTER_XT_TARGET_TPROXY=m`（`modprobe xt_TPROXY` OK）**都可用**，`xt_socket`/`nf_socket_ipv4,6`/`nf_nat`/`xt_MASQUERADE`/`iptable_nat`/`ip_set`/`xt_set` 全已加载。veth 只影响 Docker 桥接。
验证：`modinfo tun` / `modinfo xt_TPROXY`（`modinfo` 是判断「模块到底在不在」最权威的手段，比 `ls /lib/modules/` 可靠）。

**③ 存储驱动取决于分区类型，不是设置问题。**

| 机型 | data-root 落点 | 结果 |
|---|---|---|
| C2000 U | `/mnt/storage/data`（**裸 f2fs 挂载**） | **`overlay2`** ✅ |
| C2000 Max | `/opt/docker`（f2fs 之上的 overlay） | 只能 `vfs`（overlay-on-overlay 被内核拒） |

**④ 内存纪律。** C2000 U 992MB / C2000 Max 493MB（常年可用 30–80MB）。写操作前先 `free -k`，过滤清单和容器都宁轻勿重。
实测权重：jellyfin RSS 218MB → 1Panel 面板 ~70MB → clash ~65MB → dockerd ~40MB。
验证：`scripts/healthcheck_c2000u.py`（13 板块只读巡检）。

**⑤ 文件系统能力。** 支持 ext4/f2fs/vfat/fuseblk(NTFS via ntfs-3g)，**不支持 exFAT**（内核无驱动、源里也无 fuse 版）→ exFAT 的 U 盘**免格式无解**。

## 2. 应用商店与 LuCI

**① 绝不装旧版 luci-compat。** 本机 LuCI 是 git-26.224（新世代），旧包（git-22.046）`--force-overwrite` 装上去会污染 luci-base，**卸载时还会删走系统必需的 `cbi.lua` / `model/network.lua` / `view/cbi/*`** → 整个 LuCI 502。
救援：固件只读副本 `/rom` 里有一切原始文件，**只补不覆盖**地同步回 `/usr/lib/lua/luci` 即可全量恢复。

**② 商店数据只有两个文件。**
`/etc/kp_store/plugins.json`（清单，**跨行 pretty JSON**）+ `/etc/kp_store/installed.list`（已装，`|` 分隔 8 字段）。
解析坑：pretty JSON 按行 grep 只能拿到一个字段，必须先 `tr -d '\n'` 压平再 `tr '{' '\n'` 切开。

**③ 「打开」按钮点了空白 ≠ 注册失败。**
守护进程 `appcenter` 只给**远程目录**的应用下发 `luci_module_route`，本地 UCI 注册的条目拿不到，而且会把你手写的同名 option **重写丢弃**。
正路：路由写到守护进程碰不到的 `/etc/kp_store/routes.list`，再在 `controller/nradio_adv/appcenter.lua` **末尾后定义同名函数覆盖** `action_app_list_data()` 去读它（改函数体必然跟固件升级冲突）。
改完必须 `rm -rf /tmp/luci-modulecache /tmp/luci-indexcache` + `/etc/init.d/uhttpd restart`。

**④ 非 opkg 安装的应用在商店里永远「未安装」。**
「已安装」= 守护进程实时 `opkg info <子包名>`；1Panel / ocspeed 这类拷文件装的应用查无此包。
正路：造**空占位 ipk**（`Depends: libc` + `Architecture: $(DISTRIB_ARCH)`，data 里只放一个 README），已装就跳过。注释务必写明「商店里的卸载只删占位包，真正卸载走 `1pctl uninstall`」。

**⑤ 跑在独立端口的服务不能直接当「打开」目标**（同源限制 + 不是 LuCI 页面）。
正路：造**同源承载页** —— `controller/nradio_adv/<name>.lua` 注册 `template()` 路由 + `view/nradio_<name>/panel.htm` 里套一层 iframe。地址要**动态读**（如 `1pctl user-info | grep -oE 'http://[^ ]*'`）而不是写死。

**⑥ 想在路由器上做任何 WebUI，先排除 uhttpd Lua。** 固件**没有** `uhttpd_lua.so`，任何 `uhttpd_*.so` 都不存在。
可行路线：**第二个 uhttpd 实例 + CGI(ash)**：`uhttpd -f -p <lan_ip>:<port> -h <docroot> -x /cgi`，CGI 的 `PATH_INFO`/`QUERY_STRING`/`REQUEST_METHOD`/`CONTENT_LENGTH` 都可用，上传走 stdin 原始字节。

> 详见 `references/store-patching.md`、`references/istore-integration.md`、`references/kpwebui.md`

## 3. Docker 落地

**① 依赖链断裂 → stub ipk。**
`dockerd` 报 `incompatible with the architectures configured` 是**假象**，真因是 6 个 kmod（veth/dm/fs-btrfs/br-netfilter/ikconfig/nf-ipvs）在厂商内核上根本不存在。造只声明 `Provides` 的桩包把依赖链闭合是**唯一干净路径**。

**② ipk 格式：只认老式 gzip+tar 嵌套，**不认 ar 格式（deb 风格）。**
- 自造：`tarfile` 必须用 `GNU_FORMAT`/USTAR，外层 `data.tar.gz` + `control.tar.gz` 再 gzip
- 厂商 ar 包：先 `head -c 8` 判断（`!<arch>` 即 ar），PC 侧抽出三成员重打包
验证：`opkg install` 不再报 `Malformed`。

**③ 装 stub 前先移走 feed 索引。**
opkg 遇到 feed 里同名包会**优先解析 feed 候选、忽略你本地文件里的 control**（症状：报出 stub 里根本没有的依赖）。
正路：`mv /var/opkg-lists /var/opkg-lists.off` → `opkg install --force-reinstall 本地.ipk` → 还原。

**④ dockerd 配置的唯一正路：`uci set dockerd.globals.alt_config_file='/etc/docker/daemon.json'`。**
UCI 生成器只支持 data-root / log-level / iptables / bip / registry-mirrors / hosts / dns / ipv6 / ip / fixed-cidr，**没有 `storage-driver` 和 `bridge`**；init 见到 `alt_config_file` 就 `ln -s` 你的文件到 `/tmp/dockerd/daemon.json`，全文由你掌控。

**⑤ 加速源写 UCI**（`dockerd.globals.registry_mirrors`），`/tmp/dockerd/daemon.json` 每次启动重生成。
拉不动时**逐个镜像单独试**（清空 → `uci add_list` 单个 → commit → restart dockerd → 再拉），把能用的留下。

**⑥ 冒烟测试必须两步**：`docker pull` → `docker run --rm --network host`。`docker info` 通只代表守护进程活着，不代表镜像拉得下来。

**⑦ 出厂 opkg 源大概率全失效**（返回 `000` 而非 404）→ 整体换阿里云 21.02.7。

**⑧ OpenWrt 源的 `docker-compose` 是 python 版 1.28.2**，解析不了 1Panel 生成的 compose（`${VAR:+--requirepass "..."}` 这类嵌套引号 v2 语法）→ 语法解析直接失败且**面板无提示**。
正路：换官方静态二进制 compose v2（aarch64）。
⚠️ 官方 1Panel `install.sh` 的 `configure_accelerator` 会**整体覆盖 daemon.json**，别执行。

**⑨ 单个容器已知坑**（C2000 U 实测）：
- **Redis 8.x**：ARM64-COW-BUG 自检失败直接退出，检测早于配置加载 → 只能命令行传 `--ignore-warnings ARM64-COW-BUG`，且**必须放在 conf 之后**（该指令是可变参数会吃掉后面的内容）；sed 注入时**千万别用 `g`**
- **jellyfin**：启动自检要求 config 分区可用 ≥2GiB；挂到 `/overlay` 可绕过，但 992MB 机器上 RSS 218MB 实用价值低
- **filebrowser**：`-v <dir>:/database ... --database /database/filebrowser.db`（别把目录挂成文件路径），且**默认监听 127.0.0.1**，host 网络下必须 `--address 0.0.0.0`

> 详见 `references/docker-porting.md`、`references/c2000u-docker.md`、`references/c2000u-media.md`

## 4. 1Panel（v1.10.34-lts）

**① 能装。** 官方包自带 procd init，二进制静态链接可跑 musl，端口 10090。
`/usr/local/bin/1pctl` 里存着 `ORIGINAL_PORT` / `USERNAME` / `PASSWORD` / `ENTRANCE` 字面量 —— 安全入口码也能从这里读，做引导卡片时直接用。

**② 让 1Panel 应用「默认」走 host 网络：换掉 `/usr/bin/docker-compose` 为 wrapper。**
1Panel 模板一律引用外部 bridge 网络 `1panel-network` → 本机装必挂在 veth。
wrapper 在调用真件前把 `-f` 指定的 compose **幂等 host 化**（注入 `network_mode: host`、删顶层与服务级 `networks:`/`ports:`）→ 面板 / 商店 / 手工全生效，且容器由 1Panel 自己 up（会进「已安装应用」）。
真件改名保留为 `docker-compose.real`，一条命令可回滚。

**③ 转换器必须缩进无关（真机事故，血的教训）。**
**同一份应用，商店 tarball 和面板落盘的缩进不一样**：

| 来源 | 缩进 | 其它 |
|---|---|---|
| 商店 tarball | **2 空格** | 无 `deploy:` |
| 1Panel v1.10 实际落盘 | **4 空格** | 多 `deploy.resources.limits`、端口带 `${HOST_IP}:`、`networks:` 段排到最前 |

面板是「解析模板 → 套 formField → 用 Go yaml 重新序列化」，不是照抄 tarball。
旧转换器把「服务名 2 空格 / 属性 4 空格」写死 → 列 0 的顶层 `networks:`（前缀匹配，与缩进无关）**被删了**，而 `    alist:`(4) 和 `        networks:`(8) **全部漏网**，`network_mode` 也没注入 → compose v1 报 `Service "x" uses an undefined network "y"`。
**正解**：先量出服务名/属性缩进，删除按「缩进 > 服务名缩进」、注入按属性缩进。
验证：`scripts/payload/kp-compose-selftest.sh` + `fixtures/`（含事故原件），已接进 harness 的 probe 阶段。

**④ 报错文案能帮你锁定调用方。**
`Service "x" uses an undefined network` 是 **compose v1（python 1.28.2）独有**说法（v2/compose-go 写 `refers to undefined network`）→ 看到这个文案就说明**面板确实 spawn 了 `/usr/bin/docker-compose`**，wrapper 方案的前提成立。

**⑤ host 化后端口以「容器内端口」为准。**
`ports:` 段被删掉，模板里 `10443:8443` 真正监听的是**冒号右边的 8443**。面板端口字段一律填冒号右边那个数字。

**⑥ 应用表单的文本字段常有应用侧硬校验，官方 README 就是规格书。**
实例：DeepSeek Harness 的「访问地址」必须**裸 IP 或裸主机名**（不能带 `https://`、端口、路径），填成完整 URL → 入口脚本 `exit 1` + `restart: unless-stopped` → **无限重启**，而面板在 `docker-compose logs -f` 跟日志等健康检查 → UI 永远「安装中」。
诊断口诀：**「面板一直转圈 + 容器 `Restarting`」⇒ 先 `docker logs` 看容器自己为什么退出**，别查内核/网络。
另两个硬校验：用户名 `^[A-Za-z0-9._-]+$`，密码 ≥12 位。

**⑦ 参数填错也能无 UI 修复（面板登录过不去时的正路）。**
1Panel v1.10 登录有**图形验证码 + 请求体加密**两层，PC 侧 API 自动化此路不通：
- 面板库：`/mnt/storage/data/1panel/db/1Panel.db`，表 `app_installs`，**参数存在 `env` 列（JSON 字符串）里，`param` 列是空的**
- 设备**没有 `sqlite3`，但有 `python3`** → 用标准库在线改，**不必停面板、不必拷库**
- 改完同步改应用目录 `.env`，再 `docker-compose -f <应用目录>/docker-compose.yml up -d --force-recreate`

**⑧ 别误判两个正常现象**：① 应用首启前两条 healthcheck 报 `Health check exceeded timeout (5s)` 是冷启动慢，第三条即 healthy；② Caddy 按 Host 分流，从别的机器请求返回 **401（要求登录）不是失败**，恰恰证明服务活着。

**⑨ 面板驱动的安装会走我们的 wrapper** —— 取证源是 `/tmp/kp-compose.log`（wrapper 记录每次调用的完整参数）。这是「面板到底调了什么」最可靠的证据。

> 详见 `references/1panel-hostnet-default.md`、`references/c2000u-1panel.md`

## 5. DNS 与 AdGuard Home

**① 链路与切换顺序。** 设备 → AGH(:53) → OpenClash(:7874) → 上游；dnsmasq 退 :5354 只管 DHCP。
切 53 的顺序**必须先迁 dnsmasq、再重启 AGH**，否则被占。

**② AGH 改不了 DNS 端口？** 此版 API 没有监听端口字段 → 只能 sed `AdGuardHome.yaml` 的 `dns.port` 后 `docker restart`。

**③ 最隐蔽的一个坑：`/etc/init.d/firewall reload` 之后 AGH 被旁路。**
OpenClash 的 53 劫持目标取自 `DNSPORT=$(uci -q get dhcp.@dnsmasq[0].port)` —— 每次防火墙/OpenClash 重载都会把劫持**重新指向 5354**，于是 LAN 全部 53 流量（含发给 192.168.66.1:53 的）被 REDIRECT 到 dnsmasq → clash，**AGH 一个查询都收不到**。
症状极隐蔽：DNS 正常、上网正常，只是**过滤静默失效**。
正路：用 OpenClash 官方钩子 `/etc/openclash/custom/openclash_custom_firewall_rules.sh`（在官方规则**之后**执行）插 `iptables -t nat -I PREROUTING -p udp --dport 53 -j REDIRECT --to-ports 53`，让它排到官方规则前面。
验证：`iptables -t nat -S PREROUTING | grep 'dport 53'`，KP 规则行号必须小于 OpenClash 的。

**④ 清单选择看内存。** 秋风 902 条 < ADgk 9k < AdRules 19 万；可用内存 <30MB 时只加轻量清单。

**⑤ 网易云解锁保活**：AGH 域名定向 `[/music.163.com/]5354` 绕过去广告链路。

**⑥ iptables `-S` 取 comment 会多出前引号** → 用 `s/.*--comment "\([^"]*\)".*/\1/p`。

> 详见 `references/adguard-setup.md`

## 6. OpenClash 分流与自动测速

**① 「只有境外网站打不开、国内正常」的经典根因**：兜底规则 `MATCH,<代理组>` 指向的组里**当前选中了一个半死节点**。注意**跟 `GLOBAL` 无关**（那是 mihomo 内核内置组，yaml 里搜不到）。
免 SSH 定位：mihomo API `http://<ip>:9090`，头 `Authorization: Bearer <dashboard 密码>` → `GET /proxies/<组名>` 看 `now`，`GET /proxies/<名>/delay?url=http://www.gstatic.com/generate_204&timeout=5000` 现测。
治本：启用 ocspeed 的故障转移 —— `uci set ocspeed.main.failover_enable='1'` + `backup_enable='1'` → commit → **必须调 `speedswitch.sh enable`**（**没有 cron 子命令**，只有 `enable` 会 `cron_apply`）。
- **v3.4 起 `offline/ocspeed/speedswitch.sh` 已内置整套判定，装完按上面两条 uci 即可**，不需要再手工补逻辑：
  三层对照（本地链路 / 对照节点 / 当前节点多探针）全过才认定硬故障并转移，否则原样不动；
  转移后还会复测目标、明显更差则回滚。
- **本地链路对照的默认接口必须是真实出口**：多台 NRadio 上真出口是 `cpe`(proto=wwan, eth3)，
  `wan`(eth0) 恒为 `up:false` 且无默认路由 —— 若照 `wan` 写会把所有转移永久拦死。用 `uci get ocspeed.main.local_ifaces`（默认 `cpe|wan`）按需改。
- 想压住「为几十毫秒反复换节点」：调 `switch_min_interval`（分钟，两次真实切换的最小间隔；**故障转移不受它约束**，否则 MTTR 会被拖到窗口那么长）。

**② ocspeed 的「功能静默失效」三处（都修过）**
- `$DATA/running` 残留会让备用预选与故障转移**双双永久停摆且不写日志**（`running` 在 overlay 上被 kill 不掉、互斥锁在 tmpfs 上重启即清，二者不一致）→ 改为写时间戳 + 超时自愈
- **节点属性错位**：按行号配对 name/type/alive（alive 在每个节点的 history 里也有）→ 整体错位约 26%，健康节点被记成 `a:false` 而永久进不了备用池 → 改为按花括号深度解析 JSON
- **用抖动的延迟排名**：决赛组延迟抖动达 2.3 倍，50% 的切换是劣化 → 排名一律用初赛（稳定），决赛只当可用性闸门

**③ 别拿单次失败下结论。** URLTest 组自动换节点瞬间会有一次 `SSLEOFError`（0.3–0.5s 返回），几秒后自愈 → **连测 3 次**；判「通」要看 `generate_204` 是否 204。

**④ 数节点别数广告。** 订阅里混着「无法使用请升级客户端」「套餐到期」这类条目，被 mihomo 当节点列进 `all`，永远测不通 → 统计健康度时先剔除。

**⑤ 公共 subconverter 报「No nodes were found」**：上游订阅用 Cloudflare 挡转换器的 UA/IP → 别依赖公共转换器，改用 mihomo `proxy-providers`（可带自定义 `header`）。

**⑥ busybox sed 的 `a\` 会保留前导空格** → 追加 YAML 行一律顶格写（`a\text`），改完必跑 `mihomo -t` 校验再 restart。

**⑦ 装新代理/内核类服务必撞端口**：OpenClash 进程名是 **`clash`（不是 mihomo）**，占 7890-7893/9090 → 装前 `netstat -lntp` 预检，装后把新内核挪到 7897/9099（`pidof mihomo` 只能查到自装的那个）。

> 详见 `references/c2000u-openclash.md`

## 7. 存储、分区与卡故障

**① TF 卡原地扩容（4G→16G，数据零丢失）靠「NOR 窗口」。**
`resize.f2fs` 拒绝对已挂载文件系统操作（`Not available on mounted device!`），而 `/overlay` 就是 `/` 永远挂着；`pivot_tf_overlay()` 又硬编码 `/dev/mmcblk0p1`。
唯一窗口是**开机瞬间**：系统落在 `/dev/mtdblock8`（2MB jffs2）上、卡还没挂载。
四步：在线改分区表（**p1 起始扇区必须保持 16**）→ 把 `/mnt/mtdblock8/upper/etc/config/fstab` 的 `/overlay` 设 `enabled=0` 并预置脚本 + `rc.local` → reboot → 窗口内**先 umount 热插拔挂的 p1** 再 `resize.f2fs` → 恢复 fstab 再 reboot。
⚠️ 最容易漏的一步就是先 umount。

**② TF 卡**硬件级**损坏的判死三板斧**（2026-09-15 实测）。
症状：「内存卡初始化失败」+ 重启后 SSH/OpenClash/AGH/Docker 全消失但 LuCI/DNS 活着（路由器「半死」）。
判据：① `dd bs=512 count=1 skip=N | hexdump -C` 抽 MBR/p1/p2 superblock/尾扇区（本机无 base64/od）；② dd 随机 pattern 写尾部 scratch → sync → 读回 md5 对账 ×3；③ 确认 `/overlay` 丢失。
**内核仍报 `mmc0: new high speed SDHC card` 且无 I/O error，但全卡为高熵乱码、写读不回** → 判死，**不要浪费时间重建分区**。
换卡（槽支持 1GB–2TB）后用 `scripts/setup_docker_c2000u.py` 重建。

**③ 自建插件（如 ocspeed）在 overlay 重建后整目录消失且 opkg 装不回来** —— 它不在任何 opkg 源里。
三条纪律：① 源码收进自己的仓库；② **同时在数据盘留一份**（`/mnt/storage/data/*-backup/`），真断网时能原地 `cp` 回来；③ cron 由插件自己的 `enable` 重建，**别手工改 `/etc/crontabs/root`**（下次 enable 会覆盖）。

**④ 存储是可插拔 TF 卡，卡掉线时软件层无法复位**（`mtk-msdc` unbind/rebind 无效、无软件可控稳压器）→ 只能物理断电 + 重插卡。

> 详见 `references/tf-partition-resize.md`、`references/one-command-restore.md`

## 8. 无 SSH / 设备半死时的救援

**① 先区分 refused 还是 timed out。** `curl -v telnet://IP:22`：**refused** = 无监听，**timed out** = 防火墙 DROP。与本机 `nc 127.0.0.1 22` 对照 → 本机通而外部 refused 就是 `firewall` 的 `config rule 'ssh'` 在拦。

**② LuCI 能登就把它当命令通道。**
- **直读**：`GET /admin/status/dmesg` 与 `/admin/status/syslog`（服务端渲染的 textarea，**零延迟、不用等 cron**，实测 1382 行 / 117KB）
- 不够用再**借 crontab 页面**：multipart 提交 `token` + `cbi.submit=1` + `cbid.crontab.1.crons`，输出写 `/www/*.txt` 再 HTTP 读回，**收尾用一条自清理 cron**

**③ 软重启真接口是 `POST /admin/system/reboot/call`**（带 `token`，chunked 流式 200 = 已触发）；`/admin/system/reboot` 那个 URL 是假的（渲染的是 flashops）。

> 详见 `references/no-ssh-recovery.md`

## 9. 设备侧 Shell / busybox 坑

| 坑 | 说明 | 对策 |
|---|---|---|
| **能力缺失** | 无 `jq` / `timeout` / `python3` / `od` / `nft` / `base64` / `openssl` / `xxd`；`sort` 不支持 `-h`；`date` 不支持 `%N` | 用 `lua` / `awk` / `md5sum` / `cut`；计时放 PC 侧；十六进制查看放 PC 侧 Python |
| **`pgrep -c` 不支持** | 命令失败也返回 0 → **判活脚本全部误报「NOT RUNNING」** | 一律 `pidof <名> >/dev/null && echo ok`；复杂场景 `ps w \| grep '[]名' \| wc -l` |
| **不支持 `{a,b,c}` 花括号展开** | `mkdir -p /x/{l,u,w,m}` 只建了一个名叫 `{l,u,w,m}` 的目录，后续 mount 报 ENOENT，**看起来像「内核不支持 overlay」** | 路径参数一律分开写；得到否定结论前先自查命令语法 |
| **awk 对三元 + 嵌套 for/if 支持不全** | 报 `Call to undefined function` | 解析 `ls -la` 改用纯 shell：`while read -r perm lk own grp sz mo d tm name` |
| **printf 参数属于单条** | 前半段字段全空、后半段重复打印 | 每个 `printf` 自带它要用的参数 |
| **管道 while 是子 shell** | 子 shell 里改的变量回不到父 shell → 逗号全丢 | 子 shell 写临时文件，父 shell 用 `awk 'NF{c++; if(c>1) printf ","; printf "%s",$0}'` 拼 |
| **中文占 2 列但 `${#s}` 按字节算** | 右边框必然错位 | 禁止右边框和右对齐 |
| **取脚本目录禁用 `dirname`** | 固件可能没有 | 用 `${0%/*}` |

> 详见 `references/script-ui.md`、`references/pc-toolchain-limits.md`

## 10. PC 侧工具链与网络

**① Bash 工具在这台机器上基本不可用**（`dirname` / `head` / `sed` / `ls` / `du` 全缺，返回 127）→ 一律改用 PowerShell 或 **Python subprocess**（推荐，编码最可控）。

**② 中文乱码 ≠ 数据损坏。** PowerShell 控制台回显 UTF-8 中文会显示成 `鏂板` 之类，但仓库数据是正确的 UTF-8。
核对编码**只能走字节层**（Python `subprocess` 跑 `git cat-file commit HEAD` 看 hex，`e6 96 b0` = 「新」）。

**③ BOM 坑**：`Out-File -Encoding utf8` / `Set-Content -Encoding UTF8` **会写 BOM** → 用 `[System.IO.File]::WriteAllText($p,$t,New-Object System.Text.UTF8Encoding($false))` 或 Python `open(p,"w",encoding="utf-8")`。

**④ git push 输出走 stderr，PowerShell 会渲染成红色异常** —— 别用「stderr 有没有内容」判断成败，看 `git ls-remote origin refs/heads/main` 与 `git rev-parse HEAD` 是否一致。

**⑤ GitHub DNS 被污染是最常见的「push 失败」真因。**
`github.com` 解析到 `20.205.243.166` 时 443 被阻断（`Failed to connect` / `Connection was reset` / **静默 rc=128 且 stderr 全空**）。
正路：`scripts/gh_proxy_push.py push <仓库目录>` —— 起一个只监听 `127.0.0.1` 的 CONNECT 代理，把 `*.github.com:443` 强制转到可用 IP（实测 `140.82.113.3` / `140.82.114.3` / `140.82.116.3` / `20.27.177.113` / `20.200.245.247` / `4.237.22.38` / `20.248.137.48` / `20.205.243.168` 全通），**TLS SNI 仍是 github.com，证书正常**。
**绝不要用 `url.insteadOf` 换成 IP**（SNI 变 IP 必然证书失败）。
⚠️ 该脚本**只做 push/pull，从不 `git add`/`commit`** → 必须**先 commit 再调它**，推完比对 HEAD 哈希。

**⑥ 找 `gh`**：`gh.exe` 在 `C:\tmp\bin\gh.exe`（只是没进 PATH），已登录且被配成 git 的 github.com credential helper。

**⑦ 本机技能仓库 `.git` 曾离奇损坏**（`refs/` 整体消失、新 commit 对象丢失，疑似安全软件实时清除）。
修复：拿远端 sha → 手写/删除 ref 文件 → 复用 `gh_proxy_push.py` 的代理 fetch → **删 `.git/index` 强制 `add -A` 全量重建 blob** → commit → push → 循环校验。

**⑧ 沙箱拦截清单**（AI 工具调用层面，用户手动操作不受影响）：`reg.exe` 相关路径（含 `explorer.exe <url>` 打开默认浏览器）、`Add-Type`、COM 实例化、`Start-Process`、从 PowerShell 里起非 PowerShell shell。

## 11. 文件传输通道（设备无 SFTP）

`paramiko.open_sftp()` 报 `SSHException: EOF during negotiation` —— **不是权限问题，是固件根本没装 sftp-server**。四条可用通道：

| 通道 | 适用 | 要点 |
|---|---|---|
| **heredoc 分块** | 文本 | 单条 `exec_command` 超约 **8KB 会被 dropbear reset**（10KB 必挂、5KB 没事）→ 按行切 ≤4KB，首块 `>` 后续 `>>`；**body 不要再补尾换行**；切分后 `lines.pop()` 去掉末尾空元素 |
| **`printf '\NNN'`** | 二进制（小） | 固件无 base64/openssl/xxd，这是唯一通道；实测 256B / 900B 字节精确 |
| **反向 HTTP** | 大文件 / 多文件 | PC 起临时 `http.server` + 设备 `curl -o` 自拉；实测 2.86MB 秒传。两个坑：`SimpleHTTPRequestHandler` **必须传 `directory=`**；拿不到 200 多半是 **Windows 防火墙挡入站** |
| **反向隧道** | 大文件（ipk/内核镜像） | `scripts/revtunnel_put.py`：paramiko `request_port_forward` + PC `http.server` + 设备 curl + md5 对账，实测 10.2MB / 1.6s |

**从设备往 PC 取文件**：拷到 uhttpd 文档根 `/www/<tmpdir>/`，PC 用 `http://<ip>/<tmpdir>/...` 逐个 `urlopen`，拉完 `rm -rf`。文件名可能含空格，**必须 `urllib.parse.quote(url, safe=":/?&=%")`**。

> 详见 `references/pc-toolchain-limits.md`、`references/c2000u-openclash.md` §1

## 12. 调试方法论（比具体技术更值钱）

1. **「假失败」比「失败」更危险。** 花括号展开失败、`pgrep -c` 误报、fake-ip 的假连通 —— 都会让你**误判「设备不支持」**。得到否定结论前，先怀疑自己的命令语法和工具可用性。
2. **判断网络通不通，必须发真 HTTP/HTTPS 请求看响应码。** `ping` 0% 丢包、TCP 握手 0.00s 成功都可能是 fake-ip + TUN 本地代答的假象。
3. **「卡住」往往只是结果。** 面板转圈 = 面板在等健康检查；服务无响应 = 它在等服务依赖。**先看那个被等的对象为什么起不来**。
4. **取证源要选对。** 判断「面板到底调了什么」，可靠的是 `/tmp/kp-compose.log` 这类**调用日志文件**，不是 UI 表现；判断「文件是否被覆盖」，可靠的是**逐字节 md5 比对 + 多文件 mtime**。
5. **多会话并发是本机真实风险。** 曾出现「部署 md5 校验通过、几十分钟后文件整体变回旧版」——排查顺序：设备文件 md5 ↔ PC 仓库比对 → 设备多文件同 mtime 时间点 → 本机 automation 列表 → 仓库文件 mtime 是否在检查期间变化。**部署前先确认没有其他会话在动同一批文件，统一「仓库 = 唯一真源」。**
6. **只读探测先行，写操作前必备份。** 本技能包所有破坏性阶段都先跑 probe，且在写之前落一份带时间戳的 `.bak`。
7. **记录「为什么」而不是「怎么做」。** 同一台机器上，`docker run` 加不加 `--network host` 的差别是内核有没有 veth —— 记住原因，才能迁移到别的机型。

> 详见 `references/pc-toolchain-limits.md`
