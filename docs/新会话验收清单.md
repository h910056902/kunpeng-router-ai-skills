# 新会话验收清单 —— 「别的 AI 能不能读懂这个仓库」

> 用法：**开一个全新的会话**（不给任何背景、不贴本文件以外的资料），把下面 12 个问题依次问出去。
> 每题给出**期望答案要点**与**扣分项**。得分 = 答对的关键点数 / 总点数。
>
> 目的很单纯：验证本仓库的 `AGENTS.md` + `llms.txt` + `tasks/` 是否真的能让一个**零上下文的 AI**
> 找对入口、说出正确的硬约束、并给出可执行步骤。
>
> 建议提问方式：**第一句只说「看这个仓库，然后回答……」，不要提示它该读哪个文件。**

## 评分口径

| 等级 | 标准 |
|---|---|
| **A（可用）** | 9–12 题的关键点基本答全，且能主动指出「先读 AGENTS.md / tasks/index.json」 |

1. 建议容器用 bridge 网络 / 让用户去装 `kmod-veth`
2. 说设备上可以用 `sftp` 传文件
3. 建议写 `/etc/docker/daemon.json` 来改 Docker 配置（而不是 UCI 的 `alt_config_file`）

## 2. 要在上面跑容器，网络模式有什么限制？为什么？

**期望要点**
- **只能用 host 网络**
- 因为**内核没有 veth**：`CONFIG_VETH is not set`，`lsmod | grep -c '^veth'` = 0，厂商 `kmod-veth` 是**空包**
- 表现：bridge 网络起容器报 `failed to add the host (veth...) <=> sandbox (veth...) pair interfaces: operation not supported`
- **改 daemon.json / 装 kmod / `docker network create -d host` 都解决不了**（docker 只允许一个预定义 host 网络）
- 冒烟测试必须 `docker run --rm --network host`

## 5. 设备上拉 GitHub 文件有什么坑？投递大文件该怎么做？

**期望要点**
- **设备上 `curl` 拉 raw.githubusercontent.com 必失败（000），同一 URL `wget` 可以**（两条不同网络栈）→ 下载函数必须双栈
- 镜像可用：`ghfast.top` / `gh-proxy.com`
- 设备**没有 SFTP**（`open_sftp()` 报 `EOF during negotiation`），PC 的 HTTP 服务也被 Windows 防火墙拦入站
- → 大文件走 **SSH 反向端口转发**：`scripts/revtunnel_put.py`（实测 16.6MB / 2.2s）
- 单条 SSH 命令超 **~8KB** 会被 dropbear reset → 文本要按行分块（≤2.5KB）

## 7. ocspeed 的 cron 怎么建？为什么不能手工改 crontab？

**期望要点**
- 只有 `speedswitch.sh enable` / `disable` 会重建 crontab
- **没有 `cron` 子命令**（敲了只会打印 usage + `rc=1`）
- 手工改 `/etc/crontabs/root` 会被下一次 `enable` 覆盖
- 三段：`#ocspeed-auto`（自动测速）+ `#ocspeed-failover` + `#ocspeed-backup`（后两条要 UCI 里开关打开）

## 8. 1Panel 装应用报 `Service "x" uses an undefined network "1panel-network"`，为什么？怎么修？

**期望要点**
- 根因是 **compose 转换器「缩进假设」失效导致半转换**：顶层 `networks:`（列 0，前缀匹配）被删了，
  但服务级 `networks:` / `ports:` **没删**（缩进不匹配）、`network_mode: host` 也没注入
- 为什么缩进会不匹配：**商店 tarball 是 2 空格缩进，而 1Panel v1.10 落盘的 compose 是 4 空格 + 多一个 `deploy` 段**
- 修法：转换器改成**缩进无关**（先量出服务名/属性缩进再操作）；回归样本 `fixtures/compose.panel4sp.yml`
- 顺带：报错文案 `uses an undefined network` 是 **compose v1（python 1.28.2）** 的说法，
  它能出现恰好证明面板真的调了 `/usr/bin/docker-compose`（wrapper 前提成立）

**扣分**：说"去换个 compose v2 就好了"—— 实测 v1 能完整解析 1Panel 的典型 compose（`docker-compose config` 返回 0）。

## 9. Docker 的配置要写在哪？为什么？

**期望要点**
- **只认 UCI `/etc/config/dockerd`**；`/etc/init.d/dockerd` 每次启动把 UCI 渲染成 **`/tmp/dockerd/daemon.json`**
- **写 `/etc/docker/daemon.json` 完全没人读**
- 要用 UCI 生成器不支持的字段（`storage-driver` / `bridge`）→ 唯一正路是
  `uci set dockerd.globals.alt_config_file='/etc/docker/daemon.json'`
- `data-root` **必须落在 `/mnt/storage/data/docker`**（裸 f2fs）才有 **overlay2**；放 `/opt/docker` 只能 vfs

## 10. 装 Docker 时 `opkg install dockerd` 报依赖缺失，`--force-depends` 为什么没用？

**期望要点**
- 依赖链里有 6 个厂商内核根本不存在的 kmod：`kmod-veth` / `kmod-dm` / `kmod-fs-btrfs` / `kmod-br-netfilter` / `kmod-ikconfig` / `kmod-nf-ipvs`
- opkg **在「选候选包」阶段就失败**，走不到依赖检查 → `--force-depends` 只管"装包时"的检查，所以无效
- 正解：造**只声明 `Provides` 的空桩包**把依赖图闭合（`offline/stubs/` 里已备好 6 个，恰好完整）
- **装桩包前必须 `mv /var/opkg-lists /var/opkg-lists.off`**，否则被 feed 同名包截胡、报出桩里没有的依赖

## 12. 你打算怎么确认「装好了」？举一个具体的判据。

**期望要点**（任一即可，但要具体且能区分真假）
- OpenClash：`pidof clash` **且** 端口 7890/7891/7892/7893/7874/9090 在 LISTEN **且** `curl -H 'Authorization: Bearer <pw>' :9090/version` 返回 JSON
- Docker：`docker info` 里 `Storage Driver: overlay2` + `Backing Filesystem: f2fs` + `Docker Root Dir: /mnt/storage/data/docker`，**再做 `docker pull` + `docker run --rm --network host` 两步冒烟**
- 1Panel：`1pctl user-info` 有输出 **且** `curl -o /dev/null -w '%{http_code}' http://127.0.0.1:10090/` 非 000

**加分（判据质量）**
- 指出 **`docker info` 通过 ≠ 能拉镜像**，必须真拉一次
- 指出 **面板显示「运行中/安装中」永远不可信**，要用 `docker ps -a` / `logs` 复核
- 指出 **不要用 ping / TCP 握手判断出网**（fake-ip + TUN 会本地接管，0% 丢包是假象），必须发真 HTTP 看响应码
- 指出 OpenClash 启动后 30–60s 内防火墙规则未落定，此时 curl 全 000 属正常，别急着回滚
